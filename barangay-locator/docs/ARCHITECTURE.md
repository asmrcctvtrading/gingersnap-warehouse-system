# Architecture — Barangay Establishment Locator

Status: Phase 0 (planning) — decisions below drive all later phases.

## 1. Deployment target

| Item | Decision | Reason |
|---|---|---|
| Host | cPanel shared hosting (same style as the Gingersnaps warehouse system) | Owner's existing infrastructure |
| Location | `public_html/barangay/` (sub-folder) — `BASE_URL` is configurable | Same pattern as `/warehouse`, `/picklecam` |
| PHP | 8.x (select in cPanel → "MultiPHP Manager") | Spec requires 8.x |
| Database | MySQL 8 / MariaDB 10.x, `utf8mb4`, InnoDB | Spec; cPanel default |
| Runtime deps | **None.** No Composer, no Node on the server | Shared hosting; spec forbids JS frameworks |
| Local dev | Not yet verified — no PHP/MySQL could be detected on the dev machine during Phase 0 | See `KNOWN_ISSUES.md` |

## 2. Folder layout

```
barangay-locator/
├── index.php, search.php, establishment.php, map.php,
│   categories.php, services.php, directions.php, about.php   ← public pages
├── report.php                                                ← "report incorrect info" form
├── api/index.php                                             ← JSON API front controller
├── admin/                                                    ← staff dashboard (login required)
├── app/                                                      ← PHP library code (web access denied)
│   ├── bootstrap.php   config, session, autoload of lib/*
│   ├── lib/            db.php, auth.php, csrf.php, http.php, validate.php, audit.php, i18n.php, repo/*.php
│   ├── lang/           en.php, tl.php
│   └── config.sample.php   (config.local.php is generated by the installer, never committed)
├── assets/css, assets/js, assets/img
├── database/           schema.sql, migrations/, seeds/
├── install/install.php one-time web installer (self-locks)
├── storage/            logs/, uploads/ (web access denied)
├── tests/              plain-PHP test scripts (CLI)
└── docs/
```

`app/`, `storage/`, `database/`, `tests/`, `docs/` each get an `.htaccess` with `Require all denied`.

## 3. Request flow

- **Public pages**: PHP renders the shell; JavaScript calls the JSON API with `fetch` for search, filters, map markers. Pages degrade to server-rendered results when JS is off (search page does a server-side query).
- **API**: `api/index.php` parses the path (`/api/establishments/12`) from `PATH_INFO`/rewrite, falls back to `?r=establishments/12` when `mod_rewrite` is unavailable. Read-only for the public; no public write endpoint except `POST /api/reports` (rate-limited, goes to the review queue, never publishes).
- **Admin**: server-rendered PHP forms. Every handler: `requireLogin()` → `requirePermission()` → `verifyCsrf()` (POST) → PDO prepared statements → `logAudit()` → redirect. Same shape as the warehouse system.

## 4. Roles

| Role | Can |
|---|---|
| `admin` | everything incl. users, settings, categories, barangays, export |
| `verifier` | review change requests, change status, verify records, edit establishments |
| `encoder` | create / edit establishments as **Pending verification**; cannot verify or deactivate |

Users may be scoped to one barangay (`users.barangay_id`); `NULL` = all barangays.
Permissions are code constants in `app/lib/auth.php` (`can('establishments','verify')`), not a DB matrix — fewer moving parts for a 3-role system.

## 5. Data integrity rules (from the spec, enforced in code)

1. Public API returns only `status = 'verified'` **or** `pending_verification`, labelled; `inactive` and `needs_review` are hidden from public listings. (Setting `public_show_unverified` controls whether pending records appear; default **on, labelled "Not yet verified"**.)
2. Coordinates are nullable. A record without verified coordinates is listed but **never plotted**; the UI says "Location not yet verified".
3. "Officially verified" can only be set by the `verify` action, which writes a `verification_records` row (who, when, evidence/source).
4. Emergency-service flag is public only when `emergency_verified_at IS NOT NULL`.
5. Public submissions create `establishment_change_requests` (status `pending`). Nothing is published without staff approval.
6. All sample data has `is_sample = 1`, is labelled in the UI, and can be removed with one admin action.
7. Straight-line distance is never shown as walking/driving distance. Distances without a routing result are labelled "straight-line".

## 6. Security baseline

- `password_hash(PASSWORD_DEFAULT)`; login throttling (5 failures → 15-minute lock per account) + `session_regenerate_id` on login.
- Session cookie: `HttpOnly`, `SameSite=Lax`, `Secure` when HTTPS.
- CSRF token on every state-changing admin form and on public report form.
- Output escaped with `h()`; JSON via `json_encode` with `JSON_HEX_*` flags; JS builds DOM with `textContent`, not `innerHTML`, for DB-sourced strings.
- Uploads (establishment photos, optional): allow-list `jpg/png/webp`, verify with `getimagesize` + `finfo`, random file names, stored under `assets/uploads/` with no PHP execution (`.htaccess php_flag engine off` + `RemoveHandler`).
- Security headers sent from `bootstrap.php` (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, a CSP that allows the configured tile/CDN hosts).
- Installer self-locks (`storage/installed.lock`) and refuses to run twice.

## 7. Mapping decisions (details in `MAPPING_AND_GIS.md`)

- Leaflet 1.9.4, loaded from a pinned CDN URL (cdnjs / unpkg) with SRI hashes **or** vendored into `assets/vendor/` (setting decides; default CDN).
- Tile provider is a setting (`tile_url`, `tile_attribution`). Default is the public OSM tile URL **for development only**; the admin guide and README flag that production must switch to a provider that permits it (own tile server, or a commercial/free-tier provider with an API key) — OSM's tile usage policy does not allow it as unrestricted production hosting.
- Routing is a setting (`routing_provider`: `none` | `osrm` | `external_link`). Default `external_link` — "Open directions in Google/OSM" link built from verified coordinates — because a public OSRM demo server is also not for production. Embedded routes are only drawn when a routing endpoint is configured, and are labelled with mode (walking/driving) as returned by the service.
- Barangay boundary: stored as GeoJSON in `barangays.boundary_geojson` **only** if an admin supplies it with a `boundary_source`; shown with a "source: …" caption. No boundary is invented.

## 8. Internationalisation

English + Tagalog via `app/lang/*.php` arrays; language stored in session/cookie, toggle in header. Category names have `name_en` / `name_tl` columns.

## 9. Kiosk mode

Query/setting `kiosk=1` (or path `/?kiosk=1`) enables: larger touch targets, idle-timeout reset to home (`kiosk_idle_seconds`, default 90), hidden external links, optional on-screen keyboard (simple built-in JS keyboard, no dependency). Startup recipe for Windows (Chrome/Edge `--kiosk`) goes in `INSTALLATION_WINDOWS.md`.

## 10. Phases → agents (sequential execution)

Sub-agent tooling was **not confirmed available** in Phase 0, so roles are executed sequentially by the main agent. See `AGENT_TASKS.md` for the role list; no parallel agents are claimed.

## 11. Verification honesty rules for this project

- A test is "passed" only if it was actually executed; `TEST_RESULTS.md` records command + output.
- Files that were written but never executed are listed as **Not executed** in `TEST_RESULTS.md`.
